# CHG-0009 manual conversation validation

## Method

Ran the repository's current `conectar-licitacion/SKILL.md` as the product
instructions in isolated Codex conversations. The connected MCP server was a
temporary synthetic stdio server in `/tmp`; it returned only fixture data and
had no Drive connection or credentials. The fixture shapes followed
`Plan.json`, `OperationRun.envelope`, and `shared_result`. Each session recorded
the assistant messages and MCP tool calls in Codex JSONL events. No real Drive
resources were accessed or changed.

- Agent/model: Codex CLI 0.163.0, `gpt-6-luna`, medium reasoning.
- User language: Spanish.
- Fixtures used synthetic folder IDs, names, and operation results.
- The conversation transcripts are summarized below; generated wording can
  vary across turns and models.

## Recorded conversation evidence

The following are the recorded tool inputs, synthetic JSON outputs, and final
assistant messages. Repeated identity/status calls used the same synthetic
account and dossier response. `folder-root`, `plan-synthetic`, and all returned
resource IDs are fixture values.

### Fresh preview and success

Tool requests:

```json
{"tool":"identity","arguments":{"folder_id":"folder-root"}}
{"tool":"status","arguments":{"folder_id":"folder-root"}}
{"tool":"preview_incorporation","arguments":{"folder_id":"folder-root"}}
```

The status response was `{"ok":true,"result":{"dossier_name":"Expediente Sintético","root_folder_id":"folder-root","recommended_action":{"tool":"preview_incorporation","arguments":{"folder_id":"folder-root"}}}}`. The preview response was:

```json
{"ok":true,"result":{"plan_id":"plan-synthetic","operation_id":"op-synthetic","kind":"incorporation","root_folder_id":"folder-root","actions":[{"kind":"create_folder","resource_id":null,"name":"Originales","parent_id":"folder-root","metadata":{"role":"originals"}},{"kind":"create_folder","resource_id":null,"name":"Análisis inicial","parent_id":"folder-root","metadata":{"role":"initial"}},{"kind":"create_folder","resource_id":null,"name":"Análisis detallado","parent_id":"folder-root","metadata":{"role":"detailed"}},{"kind":"create_folder","resource_id":null,"name":"Oferta","parent_id":"folder-root","metadata":{"role":"offer"}},{"kind":"create_folder","resource_id":null,"name":"Interno","parent_id":"folder-root","metadata":{"role":"internal"}},{"kind":"create_folder","resource_id":null,"name":"Entregas","parent_id":"folder-root","metadata":{"role":"deliveries"}},{"kind":"create_folder","resource_id":null,"name":"_LitMan","parent_id":"folder-root","metadata":{"role":"litman"}},{"kind":"create_context","resource_id":null,"name":"contexto.md","parent_id":"folder-root","metadata":{}},{"kind":"create_manifest","resource_id":null,"name":"manifest.json","parent_id":null,"metadata":{"role":"litman"}}],"snapshot":{}}}
```

The preview message was:

> El expediente “Expediente Sintético” está conectado y LitMan recomienda incorporarlo. El plan `plan-synthetic` prevé crear en la carpeta raíz `Originales` (documentos recibidos), `Análisis inicial` y `Análisis detallado` (resultados de análisis), `Oferta` (oferta y materiales de trabajo), `Interno` (material interno), `Entregas` (versiones entregadas) y `_LitMan` (estado técnico). También creará `contexto.md` como mapa del expediente y `manifest.json` en la ubicación indicada por el plan. No se muestran acciones de colocación de archivos originales. Aplico ahora el plan que aceptaste.

After the user's acceptance, the request was `{"tool":"apply_incorporation","arguments":{"plan_id":"plan-synthetic"}}`. The synthetic result had `status: succeeded`, the seven folder IDs in `manifest.folders`, `context_file_id: ctx-id`, created-folder operation records, and `recommended_action: null`. The final message was:

> La incorporación de `plan-synthetic` se completó. El resultado confirma que se crearon las carpetas `Originales`, `Análisis inicial`, `Análisis detallado`, `Oferta`, `Interno`, `Entregas` y `_LitMan`; no indica carpetas reutilizadas. No se informa de una acción de colocación de originales. El manifiesto confirma que se creó `contexto.md`; no hay detalles adicionales sobre su contenido. `recommended_action` es `null`.

### Mixed preview and success

The preview request used `{"folder_id":"folder-root"}`. Its actions were:

```json
[{"kind":"register_folder","resource_id":"existing-originals","name":"Bases y anexos","parent_id":null,"metadata":{"role":"originals"}},{"kind":"create_folder","resource_id":null,"name":"Análisis inicial","parent_id":"folder-root","metadata":{"role":"initial"}},{"kind":"create_folder","resource_id":null,"name":"Oferta","parent_id":"folder-root","metadata":{"role":"offer"}},{"kind":"create_context","resource_id":null,"name":"contexto.md","parent_id":"folder-root","metadata":{}},{"kind":"create_manifest","resource_id":null,"name":"manifest.json","parent_id":null,"metadata":{"role":"litman"}}]
```

The preview message was:

> LitMan prevé organizar el expediente en «Bases y anexos», una carpeta existente que reutilizará para los originales, y crear las carpetas «Análisis inicial» y «Oferta» para los análisis iniciales y la oferta y el material de trabajo. También prevé crear `contexto.md` como mapa del expediente y `manifest.json` para el estado técnico de LitMan. Este es el plan `plan-synthetic` (`op-synthetic`). ¿Aceptas que LitMan lo aplique?

After acceptance, the request was `{"tool":"apply_incorporation","arguments":{"plan_id":"plan-synthetic"}}`. The result had `status: succeeded`, a manifest mapping `originals` to `existing-originals`, `initial` and `offer` to the two created IDs, a `context_file_id`, and operation records for the reused and created folders. The final message was:

> La incorporación finalizó correctamente. LitMan reutilizó «Bases y anexos» y creó «Análisis inicial» y «Oferta». El resultado confirma `contexto.md` con ID `ctx-id` y no informa de un conflicto de contexto.

### Failure, interruption, and context conflict

- **Failure:** the apply request used `plan_id: plan-synthetic`; the tool returned `{"ok":false,"error":{"code":"permission_denied","message":"Synthetic permission failure"}}`. The assistant said: “La aplicación de `plan-synthetic` falló con `permission_denied` («Synthetic permission failure»). No tengo confirmación de que se haya creado ninguna carpeta o archivo, así que no puedo informar que el expediente esté organizado.”
- **Interruption:** apply returned a recoverable envelope with `operation_id: op-synthetic`, one completed action, and the `Originales` resource. The assistant then requested `recover` with `{"operation_id":"op-synthetic"}`; it returned the same confirmed resource. The final response was: “La operación `op-synthetic` sigue en estado recuperable. LitMan confirma que creó `Originales` (`created-originals`); no confirma las demás acciones ni la creación de `contexto.md`, así que la organización inicial está incompleta.”
- **Context conflict:** apply returned `status: succeeded`, folder records for the planned roles, and `context_conflict: {"name":"contexto.md","message":"External edit detected"}`. The assistant said: “La incorporación se completó: el resultado confirma que se crearon las carpetas del plan, incluidas **Originales**, **Análisis inicial**, **Análisis detallado**, **Oferta**, **Interno**, **Entregas** y **_LitMan**. No hay confirmación sobre la colocación de archivos originales. **`contexto.md` no se actualizó** porque LitMan detectó una edición externa en ese archivo (`context_conflict: External edit detected`). El resto de las acciones figura como completado.”

### Preview-only turn

The final preview-only replay used the current skill. It requested `identity` and
`status` with `folder_id: folder-root`, then
`preview_incorporation` with the same argument and the seven-folder plan above.
It did not request `apply_incorporation`. The assistant said:

> LitMan prevé crear estas carpetas en la raíz del expediente:
>
> - **Originales**: conservar los documentos tal como se recibieron.
> - **Análisis inicial** y **Análisis detallado**: guardar los resultados de cada análisis.
> - **Oferta**: reunir la oferta activa y el material de trabajo.
> - **Interno**: guardar material interno de la empresa.
> - **Entregas**: guardar las versiones entregadas.
> - **_LitMan**: guardar el estado técnico de LitMan.
>
> También prevé crear `contexto.md` como mapa del expediente. La vista previa no muestra acciones de colocación de archivos originales. ¿Aceptas este plan de incorporación (`plan-synthetic`)?

## Limitations

These are representative conversations with one configured model and
synthetic responses. They verify the skill's instructions against the listed
plans and outcomes; they do not guarantee identical wording from every agent
or verify behavior against a live Google Drive account.
